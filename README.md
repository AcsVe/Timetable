# نظام جدولة الحصص وتوزيع المعلمين — Timetable

Flask + SQLAlchemy + Postgres (Neon) · واجهة عربية RTL مع الإنجليزية · مستقل عن مشروع عربة الحواسيب.

مخطط قاعدة البيانات المعتمد: [`docs/ERD.md`](docs/ERD.md).

## الحالة: المرحلة 1 — الخادم والكيانات الأساسية ✅

| الجزء | ما تم |
|---|---|
| البنية | UUIDv7 لكل سجل، `version` (قفل تفاؤلي ← 409)، `change_seq` عام للمزامنة، حذف ناعم، سجل تدقيق لكل تعديل |
| الاتصال | كل عملية تعديل تتطلب `Idempotency-Key`؛ إعادة نفس الطلب تُرجع النتيجة المخزّنة ولا تُنفَّذ مرتين |
| الحسابات | `admin` / `stage_editor` (مراحل محددة) / `viewer`، حسابات بديلة بتاريخ انتهاء `valid_until` |
| البيانات | المدرسة، السنوات، الفصول، الأيام، المراحل، الصفوف، الشعب، التقسيمات والمجموعات، المباحث، المعلمون، المباني، القاعات، قوالب التوقيت وربطها بالأيام/الصفوف دفعة واحدة |
| الجدولة | الدروس ← البطاقات تلقائياً (5 حصص مزدوجة = 2+2+1)، وضع/نقل/قفل البطاقات، دروس مشتركة، مجموعات بنفس الحصة (رياضة أولاد/بنات، موسيقى/دراما) |
| منع التعارض | محرّك قواعد واحد (معلم، قاعة، شعبة/مجموعة، توقيت، فسحة داخل الحصة المزدوجة، أوقات عدم التوفر، نوع القاعة) + قيد `EXCLUDE` في قاعدة البيانات يمنع حجز المعلم/القاعة مرتين حتى عند الحفظ المتزامن |
| السحب والإفلات (الخادم) | `POST /api/cards/<id>/check` فحص قبل الإفلات، و`GET /api/cards/<id>/allowed-slots` شبكة الخانات المسموحة مع السبب |
| التحقق | تقرير أخطاء/تحذيرات + فحص جدوى حسابي (نصاب المعلم مقابل خاناته، حصص الشعبة مقابل أسبوعها) |
| دورة الجدول | نسخ جدول كمسودة، نشر (يؤرشف المنشور السابق، ويرفض النشر مع وجود أخطاء إلا بـ `force`)، الجداول المؤرشفة للقراءة فقط |
| المزامنة | `GET /api/sync?since=N` يعيد كل التغييرات (مع المحذوفات) بالترتيب — أساس العرض دون اتصال |

## الحالة: المرحلة 2 — الواجهة الإدارية ✅

| الشاشة | ما تتيحه |
|---|---|
| شبكة الجدول | عرض حسب الشعبة / المعلم / القاعة؛ سحب وإفلات، أو ضغطة على الحصة ثم ضغطة على الخانة (للجوال)؛ عند اختيار حصة تتلوّن الخانات: أخضر مسموح، أحمر فيه تعارض مع سببه؛ قفل الحصة؛ صندوق "غير موضوعة" |
| الدروس والتوزيع | إضافة/تعديل الدروس (مبحث، معلمون، شعب أو مجموعات، دروس مشتركة، مفردة/مزدوجة)، تصفية، ملخص نصاب المعلمين |
| التحقق | الأخطاء والتحذيرات مع زر "عرض في الجدول" |
| الجداول | مسودة/منشور/مؤرشف، نسخ، نشر |
| توقيت الحصص | قوالب توقيت (إنشاء سريع: بداية + عدد + مدة + فسح)، تعديل الحصص، شبكة (صف × يوم) + تطبيق قالب على عدة أيام وصفوف دفعة واحدة |
| أوقات عدم التوفر | شبكة لكل معلم/شعبة/قاعة/مبحث |
| الإعداد | المراحل، الصفوف، الشعب، التقسيمات والمجموعات، المباحث، المعلمون، القاعات، السنوات، الفصول، الأيام، المباني، المستخدمون، بيانات المدرسة |
| عام | عربي RTL مع تبديل للإنجليزية، متجاوب مع الجوال، PWA قابل للتثبيت، عرض آخر بيانات محمّلة دون اتصال مع منع الحفظ برسالة واضحة |

جرّب ببيانات تجريبية: `flask --app wsgi.py seed-demo --admin-email you@school`

## الحالة: المرحلة 3 — التقارير والتصدير ✅

| التقرير | المحتوى |
|---|---|
| الجدول الأسبوعي للشعبة | صفحة لكل شعبة، مع أوقات الحصص الفعلية |
| جدول حصص المعلم | صفحة لكل معلم (نصابه الأسبوعي كاملاً) |
| جدول إشغال القاعة | صفحة لكل قاعة |
| توزيع المعلمين على الشعب | مصفوفة: المعلم × الشعبة ← عدد الحصص |
| توزيع المعلمين على المباحث | كل مبحث مع معلميه وشعبهم |
| إحصائيات المعلمين والنصاب | المُسنَد، المُدرَج، النصاب، الفرق، النسبة |
| إحصائيات المباحث | عدد المعلمين والشعب والحصص لكل مبحث |
| تغطية الحصص في الشعب | المطلوب، المُدرَج، نسبة التغطية، الخانات الفائضة |

- تصفية كل تقرير حسب المرحلة / الصف / الشعبة / المعلم / المبحث / القاعة.
- معاينة على الشاشة، وطباعة مباشرة، وتصدير **Excel** (بيانات حقيقية في خلايا، ورقة من اليمين إلى اليسار) و**PDF** (عربي سليم الحروف والاتجاه)، بالعربية أو الإنجليزية.
- **شعار المدرسة** يُرفع من "بيانات المدرسة" ويظهر في رأس كل ملف Excel وPDF.
- PDF بمكتبة ReportLab (بايثون خالصة، لا تحتاج مكتبات نظام على Render)، بخط Noto Naskh Arabic للعربية وDejaVu Sans للاتينية (رخص مفتوحة مرفقة في `app/reports/fonts`).

**التالي:** المولّد التلقائي للجدول.

## الحالة: المرحلة 7 — تنبيهات الجوال (Web Push) والأعداد في كل قائمة ✅

| الجزء | ما تم |
|---|---|
| تنبيهات الجوال والحاسوب | من جرس الإشعارات: «تفعيل التنبيهات على هذا الجهاز»، ثم تصل كل رسالة داخل النظام (حصص الإشغال، المراقبة، المناوبة) تنبيهاً على الجهاز حتى والنظام مغلق، وفتحها ينقل إلى الصفحة المعنية. «تنبيه تجربة» و«إيقاف» لكل جهاز. على iPhone/iPad يلزم إضافة النظام إلى الشاشة الرئيسية أولاً. |
| التنفيذ | Web Push قياسي (VAPID + تشفير aes128gcm) مبني على مكتبة `cryptography` وحدها، بلا مكتبات تحتاج بناءً على الخادم. تُنشأ مفاتيح VAPID تلقائياً وتُحفظ (أو تُعطى في `VAPID_PUBLIC_KEY` / `VAPID_PRIVATE_KEY`)، والمفتاح الخاص لا يُعرض. ويُحذف الجهاز الذي ألغى اشتراكه تلقائياً. |
| الأعداد | كل قائمة تعرض «العدد الإجمالي»، و«المعروض: س من ص» عند البحث، و«المحدد». وكل قائمة تصفية تعرض «الكل (العدد)» وعدد السجلات بجانب كل خيار (الشعب، المراحل، المعلمين، المباحث، الفصول)، وقائمة الشبكة تعرض المُدرَج من المطلوب لكل شعبة أو معلم أو قاعة. وقوائم الاختيار المتعدد تعرض «المحدد: س من ص» مع «تحديد الكل»، والتقارير تعرض عدد الصفوف في المعاينة وPDF وExcel. |

## الحالة: المرحلة 6 — البريد عبر Microsoft 365، والطلبة، والاستيراد حسب المراحل والشعب ✅

| الجزء | ما تم |
|---|---|
| البريد (Microsoft Graph) | تسجيل تطبيق في المستأجر (Tenant) بصلاحية Mail.Send من نوع Application؛ الإعداد من صفحة «البريد عبر Microsoft 365» (للمدير) أو من متغيرات البيئة `MS_TENANT_ID` و`MS_CLIENT_ID` و`MS_CLIENT_SECRET` و`MS_MAIL_SENDER` (لها الأولوية). السر لا يُعرض بعد حفظه. زر لإرسال رسالة تجربة يُظهر خطأ Microsoft بالتفصيل، وسجل لكل رسالة (أُرسلت / فشلت وسببه). |
| الإبلاغ | نافذة واحدة لإبلاغ البدلاء (حصص الإشغال)، والمراقبين (جدول الامتحانات)، والمناوبين (جدول المناوبة): معاينة رسالة كل معلم، واختيار المعلمين، والإرسال بالبريد و/أو إشعار داخل النظام، ثم نتيجة كل معلم (أُرسل، فشل، لا يوجد بريد). الرسالة HTML من اليمين إلى اليسار مع رابط إلى الصفحة. |
| الطلبة | شاشة «الطلبة»: رقم الطالب، الاسم، الجنس، الشعبة، المجموعات، هاتف ولي الأمر؛ بحث فوري، وتحديد متعدد مع حذف جماعي و«نقل المحدد إلى شعبة» (تتبع المجموعات الجنس تلقائياً)، وتقرير «قوائم الطلبة حسب الشعب» (صفحة لكل شعبة). يُحدَّث عدد طلبة الشعبة والمجموعة من القائمة. |
| استيراد الطلبة | ورقة «الطلبة» في القالب أو أي ملف Excel/CSV فيه اسم الطالب والصف والشعبة: تُنشأ المرحلة والصف والشعبة الناقصة، ويُطابَق الطالب برقمه أو باسمه في شعبته (فلا يتكرر عند إعادة الاستيراد، ويُنقل إذا تغيّرت شعبته)، وتُوزَّع مجموعات البنين/البنات حسب الجنس. |
| استيراد المعلمين حسب المراحل والشعب | أعمدة «المراحل» و«الشعب» (تضيف مراحل تلك الشعب) و«مربي الشعبة»؛ والمرحلة المختارة قبل الاستيراد تُضاف لمن لم تُحدَّد مرحلته. |

## الحالة: المرحلة 5 — الغياب وحصص الإشغال (البدلاء) ✅

| الجزء | ما تم |
|---|---|
| تسجيل الغياب | لمعلم أو لعدة معلمين دفعة واحدة، ليوم أو لعدة أيام، كاملاً أو من حصة إلى حصة، مع السبب من قائمة تعدّلها المدرسة (إجازة مرضية، مهمة رسمية، دورة…) وحقول إضافية. |
| الحصص المتأثرة | تظهر تلقائياً كل حصة فقدت معلمها في ذلك اليوم (بحسب الجدول ويوم الأسبوع ودورة أسبوع أ/ب)، مع وقتها وشعبتها ومبحثها. |
| اقتراح البديل | قائمة مرتبة لكل حصة مع أسباب الترتيب وتنبيهاته: يُستبعد من يدرّس في الحصة نفسها أو الغائب أو من يغطي حصة أخرى؛ ويُفضَّل الموجود في المدرسة ذلك اليوم، ومن يدرّس المبحث أو الشعبة نفسها، ومن المرحلة نفسها، والأقل حصصاً في يومه، والأقل إشغالاً في الأسبوع والفصل؛ ويُنبَّه إلى المناوب في ذلك الوقت أو من يتجاوز حده اليومي. |
| التوزيع التلقائي العادل | زر واحد يوزّع كل الحصص المفتوحة (أو المحددة منها)، فيبدأ بالحصص الأقل خيارات ويوازن عدد الإشغال بين المعلمين؛ والحصة التي فيها معلم مشارك حاضر تُسجَّل «لا تحتاج إلى بديل». ويمكن التراجع عن التوزيع التلقائي وحده. |
| قرارات أخرى | دمج مع شعبة أخرى، إلغاء الحصة، لا تحتاج إلى بديل، تغيير القاعة، وملاحظة؛ وتحديد متعدد لإلغاء حصص أو حذف قرارات دفعة واحدة. يمنع الخادم إسناد بديل مشغول. |
| الإبلاغ | رسالة جاهزة لكل بديل (نسخ، واتساب، بريد)، وتسجيل الإبلاغ، وإشعار داخل النظام لمن له حساب (جرس الإشعارات أعلى الصفحة). |
| التقارير | ورقة الإشغال اليومية (بخانة توقيع البديل، بالأبيض والأسود)، وعدد حصص الإشغال والغياب لكل معلم لفترة، وسجل غياب المعلمين، و«المعلمون المتاحون في كل حصة» ليوم محدد. |
| الصلاحيات | محرّر المرحلة يسجّل الغياب لمعلمي مرحلته، ويقرّر الإشغال لحصص مرحلته فقط. |

## الحالة: المرحلة 4 — الامتحانات والمناوبة وقواعد النصاب وتطوير التقارير ✅

| الجزء | ما تم |
|---|---|
| قواعد النصاب الأسبوعي | قاعدة لمرحلة أو مبحث أو معلم أو عدة معلمين (أو مزيج منها): عدد محدد، أو بين حدّين، أو «لا يقل عن» / «لا يزيد على»، أو النصاب المسجّل لكل معلم، مع سماح ± حصة. تُحتسب جميع حصص المعلم أو حصص النطاق فقط، من المُسنَد أو المُدرَج. وتُطبَّق القاعدة الأخص (المعلم ← المبحث ← المرحلة ← الجميع). |
| إشعار الاكتمال والنقص والزيادة | لكل معلم ولكل قاعدة (المبحث / المرحلة / المجموعة): يظهر بالنص أو باللون أو بهما، بكلمات المدرسة وألوانها، في صفحة «قواعد النصاب» والدروس وشبكة الجدول والتحقق والتقارير. |
| جدول الامتحانات | لكل فصل دراسي: التاريخ واليوم والجلسة والوقت والمرحلة والصفوف والمبحث، وقاعات متعددة لكل امتحان (القاعة، الموقع، الشعب، المعلمون المراقبون). تنبيه إلى المراقب أو القاعة أو الشعبة المحجوزة مرتين في الوقت نفسه، وإلى القاعة بلا مراقب. نسخ امتحانات فصل إلى آخر مع تحريك التواريخ. |
| جدول المناوبة | لكل فصل دراسي: اليوم (أو كل الأيام)، الغاية (استقبال الطلبة، الطابور، الاستراحات، الأنشطة، الممرات، المغادرة…)، الموقع بطوابقه وممراته، الفترة والوقت، المرحلة، المعلمون. عرض حسب الأيام كالجدول المطبوع، أو قائمة بتحديد متعدد. تنبيه إلى المعلم المناوب في مكانين في الوقت نفسه أو في أثناء حصة له. نسخ من فصل إلى آخر. |
| تخصيص مرن | تغيير مسميات الحقول واسم الشاشة والتقرير، وتحرير القوائم (عنصر في كل سطر، والعنصر الفرعي يبدأ بشرطة: «الطابق الأول › الممر الشرقي»)، وإضافة حقول إضافية بأنواع مختلفة، ويمكن جعل الحقل فرعياً تحت حقل آخر. |
| ألوان شبكة التوزيع | لون لكل مبحث، أو لكل معلم، أو «المبحث ومعلموه» (درجات من لون المبحث لكل معلم)، أو بلا ألوان؛ لوحة لتغيير أي لون مباشرة، وزر «ألوان متباينة تلقائياً». |
| التقارير | نمط «أبيض وأسود بلا خلفيات» افتراضياً (جداول صافية للطباعة) أو ملوّن؛ تبديل الاتجاه في كل الجداول (الأيام صفوفاً/أعمدةً، الشعب أو المعلمون صفوفاً/أعمدةً، وتبديل الصفوف والأعمدة في المصفوفات)؛ اختيار محتوى الخانة؛ خانات توقيع. تقارير جديدة: جدول المبحث، الجدول العام للمرحلة وللمعلمين، المعلمون المتاحون في كل حصة، توزيع حصص المعلم على الأيام والفجوات، اكتمال النصاب، الامتحانات، المراقبة، المناوبة، مناوبات كل معلم. |
| توقيت الحصص | تعديل اسم قالب التوقيت ومرحلته، وعمود المدة، وتحريك أوقات الحصص التالية تلقائياً، وإدراج حصة أو استراحة بين الحصص. |
| القوائم | بحث فوري (يعمل على الجوال) وتحديد بمربعات اختيار مع «تحديد الكل» وحذف جماعي في كل قوائم الإعداد والدروس والامتحانات والمناوبة والقواعد؛ وبحث داخل قوائم الاختيار الطويلة. |

## الاستيراد (Excel وCSV وaSc Timetables) ✅
- صفحة «الاستيراد» (للمشرف): اختيار الملف، ثم معاينة تعرض ما سيُضاف أو يُحدَّث أو يبقى بلا تغيير، مع الأخطاء والتنبيهات مرقَّمة بالسطر، ثم التأكيد. ولا يُحفظ شيء قبل التأكيد.
- **Excel ‏(.xlsx)**: قالب جاهز من `/api/import/template.xlsx` فيه ورقة لكلٍّ من المباحث والقاعات والمعلمين والشعب والدروس، وتُفهَم العناوين بالعربية أو الإنجليزية.
- **CSV**: جدول واحد بالعناوين نفسها (UTF-8 أو ترميز ويندوز العربي، والفاصل «,» أو «;»).
- **aSc Timetables**: ملف XML المُصدَّر من aSc (ملف ← تصدير ← aSc Timetables XML). يُستورد كل شيء: الحصص وأوقاتها، والمباحث، والمعلمون، والقاعات، والصفوف والشعب، والتقسيمات والمجموعات، والدروس، والبطاقات الموزعة. البطاقة التي تتعارض تبقى غير موزعة ويُنبَّه إليها. ويُقبل ملف `.roz` إذا كان XML (عادياً أو مضغوطاً)؛ أما الصيغة الثنائية المغلقة فيُطلب تصديرها XML.
- إعادة الاستيراد لا تكرر شيئاً: تُطابَق الأسماء (مع تجاهل التشكيل وصور الهمزة)، ويُطابَق الدرس بالمبحث والشعب والمعلمين. والخانة الفارغة لا تمحو القيمة المحفوظة.

## التشغيل محلياً

```bash
pip install -r requirements-dev.txt
export DATABASE_URL=postgresql://USER:PASS@HOST/DB      # Postgres 15+ (NULLS NOT DISTINCT)
flask --app wsgi.py db upgrade
flask --app wsgi.py seed-base                          # الأيام (الأحد–الخميس دوام) والإعدادات
flask --app wsgi.py create-admin --email you@school --password '...'
flask --app wsgi.py run
```

تُبنى قاعدة الاختبار من ملفات الـ migrations نفسها، فالاختبارات تثبت صحة الـ migrations أيضاً.
اختبارات المتصفح (`tests/e2e`) تشغّل الواجهة فعلياً في Chromium عبر Playwright: السحب والإفلات، التعارضات، اللغتين، ووضع عدم الاتصال.

## النشر على Koyeb + Neon (الموصى به)

1. **Neon:** مشروع في Frankfurt (eu-central-1)، وانسخ رابط الاتصال `postgresql://…?sslmode=require`.
2. **Koyeb:** Create Web Service ← GitHub ← `AcsVe/Timetable`، فرع `main`.
   - Builder: **Dockerfile** (الملف موجود في جذر المستودع).
   - Instance: **Free**، Region: **Frankfurt**.
   - Port: **8000** (HTTP)، Health check: HTTP على المسار `/healthz`.
3. Environment variables (والحساسة منها كـ Secret):
   `DATABASE_URL`، `SECRET_KEY` (نص عشوائي طويل)، `INITIAL_ADMIN_EMAIL`، `INITIAL_ADMIN_PASSWORD`، واختيارياً `SEED_DEMO=1`.
4. Deploy. عند كل تشغيل تُنفَّذ الـ migrations، ويُنشأ المدير الأول مرة واحدة فقط.
5. بعد أول دخول: احذف `INITIAL_ADMIN_PASSWORD`، وأعد `SEED_DEMO` إلى `0`.

الخادم المجاني في Koyeb: ‏512MB، ‏0.1 vCPU، ويتوقف بعد ساعة بلا زيارات ثم يعود مع أول طلب.
على خادم أكبر يمكن رفع `WEB_CONCURRENCY` (عدد العمليات).

## النشر على Google App Engine + Neon

الحصة المجانية: 28 ساعة تشغيل F1 يومياً و1GB نقل صادر يومياً (≈30GB شهرياً)؛ يتطلب حساب فوترة (بطاقة) ولا تُحتسب رسوم ضمن الحصة.
من **Cloud Shell** في المتصفح:
```
git clone https://github.com/AcsVe/Timetable && cd Timetable
cp secrets.yaml.example secrets.yaml && nano secrets.yaml      # أدخل القيم
gcloud app create --region=europe-west3                         # مرة واحدة فقط (فرانكفورت)
gcloud app deploy
```
للتحديث لاحقاً: `git pull && gcloud app deploy`.

## النشر على Render + Neon (بديل)

`render.yaml` جاهز: New ← Blueprint ← المستودع، ثم أدخل `DATABASE_URL` و`INITIAL_ADMIN_EMAIL` و`INITIAL_ADMIN_PASSWORD`.

## ملخص الـ API

كل الكتابات: ترويسة `Idempotency-Key: <uuid>`، والتعديل/الحذف يحتاج `version` الحالي.
الأخطاء بصيغة موحّدة: `{"error", "message" (عربي), "message_en", "details"}`.

|---|---|
| `POST /auth/login` · `POST /auth/logout` · `GET /auth/me` | الدخول |
